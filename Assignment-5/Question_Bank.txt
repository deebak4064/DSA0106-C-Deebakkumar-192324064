UNIT V: Virtual Functions, Polymorphism & Exception Handling
Question Bank: Debugging & Pseudo-Code Formulation (Questions Only)

1. Syllabus & Topic Scope
• Virtual Functions: Purpose and need for virtual functions, static/early binding vs. dynamic/late binding, member function dynamic dispatch.
• Internal Mechanics of Virtual Functions: Virtual method table (vtable), virtual table pointer (vptr), compiler overhead and indirection cost.
• Virtual Destructors: Why base classes with virtual functions require virtual destructors, preventing undefined behavior and memory leaks during polymorphic deletion via base pointers.
• Pure Virtual Functions: Syntax (virtual void func() = 0;), semantic role in defining pure abstract interfaces.
• Runtime Polymorphism: Achieving uniform runtime interfaces using base class pointers and references pointing to derived class instances.
• Exception Handling Mechanism: Philosophy of structured error handling, try, catch, and throw keywords, control flow transfer during exceptions.
• Stack Unwinding: Automatic destruction of local stack objects during exception propagation.
• Throwing, Catching & Rethrowing Exceptions: Throwing primitive values, standard library exceptions, and custom exception classes; catching by reference to prevent object slicing; rethrowing exceptions using bare throw; vs. copy-slicing throw e;.
• Catch-All Handler (catch(...)): Universal catch block, placement as the final fallback.
• Order of Catch Handlers: Subclass-before-superclass catch ordering requirement to prevent unreachable handlers.
• Specifying Exceptions: Dynamic exception specifications (historical context) and modern noexcept specifiers.

2. Assessment Instructions & Rules ("How to Do & What to Do")
A. Instructions for Debugging Questions
When debugging runtime polymorphism and exception handling in C++:
1. Verify Virtual Destructor Presence:
• Inspect base classes designed for polymorphic deletion (delete basePtr;). If the base class destructor is not declared virtual, the derived class destructor will NOT execute, resulting in memory leaks and Undefined Behavior.
2. Inspect Catch Handler Ordering:
• Check the order of catch blocks. In C++, catch handlers match sequentially. If a base class exception handler (catch (const BaseException &e)) precedes a derived class handler (catch (const DerivedException &e)), the derived handler is unreachable.
3. Examine Exception Rethrowing:
• Inspect catch blocks that rethrow exceptions. Writing throw e; creates a copy with the static type of e, causing Exception Slicing. To preserve the dynamic derived exception type, bare throw; must be used.
4. Identify Abstract Class Instantiation:
• Check whether a derived class inherits pure virtual functions (= 0). If the derived class fails to provide an implementation for even a single pure virtual function, it remains an abstract class and cannot be instantiated directly.
5. Inspect Polymorphic Parameter Passing:
• Verify whether functions accepting polymorphic objects take them by reference (const Base&) or by pointer (Base*). Passing by value (Base b) triggers object slicing and suppresses dynamic binding via vtable.
6. Required Output Format:
• State line numbers and classify the bug.
• Provide the theoretical analysis referencing vtable/vptr mechanics or exception handling runtime semantics.
• Provide the corrected C++ code.
• Provide the dry run and terminal output.
B. Instructions for Pseudo-Code Writing Questions
1. Polymorphic Architecture Modeling:
• Define abstract interfaces using ABSTRACT CLASS and PURE VIRTUAL METHOD method().
• Model derived overrides with OVERRIDE METHOD method().
• Include virtual destructors: VIRTUAL DESTRUCTOR().
2. Exception Flow Modeling:
• Use standard exception handling syntax: TRY, THROW NEW ExceptionType(...), CATCH (e AS ExceptionType), RETHROW, CATCH (...).
3. Traceability:
• Include a trace table tracking control jumps during normal execution, exception throw events, stack unwinding destruction, and catch handler execution.
