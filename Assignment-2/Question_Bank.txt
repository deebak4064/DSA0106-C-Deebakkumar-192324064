UNIT II: Functions and Classes & Objects in C++
Question Bank: Debugging & Pseudo-Code Formulation (Questions Only)

1. Syllabus & Topic Scope
• The Main Function: Signatures (int main(), int main(int argc, char* argv[])), return codes, execution lifecycle.
• Function Prototyping: Declaration vs. definition, parameter lists, type safety.
• Call by Reference: Syntax using references (&), memory alias semantics, avoiding copy overhead.
• Return by Reference: Returning lvalues, lvalue assignment (func() = val), risks of dangling references to local stack frames.
• Inline Functions: Syntax, compiler expansion heuristics, inline member functions, limitations (loops, recursion, static variables).
• Default Arguments: Placement in declarations, trailing argument rule, avoiding redeclaration conflicts.
• Function Overloading: Signature differentiation (types, count of parameters), resolution mechanics, ambiguity traps caused by default arguments and implicit type conversions.
• Specifying a Class & Member Functions: Class anatomy, access specifiers (private, public, protected), defining member functions inside vs. outside class using scope resolution (::).
• Arrays within a Class: Internal buffer storage, bounds containment, member methods manipulating internal arrays.
• Static Member Functions & Static Data Members: Class-level storage, external definition requirement, invocation via class scope (Class::Function()), absence of this pointer in static member functions.
• Arrays of Objects: Multi-instance allocation, dependency on default constructors, indexed manipulation.
• Friendly Functions: The friend keyword, granting non-member access to private/protected state, friend functions as bridges between classes.

2. Assessment Instructions & Rules ("How to Do & What to Do")
A. Instructions for Debugging Questions
When debugging functions, classes, and object interactions in C++, apply the following diagnostic methodology:
1. Analyze Lifetime & Scope:
• Inspect functions returning by reference (Type&). Verify whether the returned object resides in the caller's stack frame, heap memory, or static storage. If it returns a local automatic stack variable, flag it as a Dangling Reference causing Undefined Behavior.
2. Inspect Static Member Constraints:
• For static data members: Check if the member is only declared inside the class header or also defined and initialized at file scope outside the class. (Missing file-scope definition causes a Linker Error).
• For static member functions: Verify whether they attempt to access instance variables (this->member) or invoke non-static member functions without an explicit object instance.
3. Verify Overload Resolution & Defaults:
• Check whether default arguments cause two function signatures to become indistinguishable when called with fewer arguments (ambiguity).
4. Verify Object Array Initializability:
• If an array of objects is declared (e.g., Class arr[10];), verify whether the class possesses an accessible Default Constructor (zero arguments).
5. Inspect Friend Function Mechanics:
• Remember that a friend function is NOT a member function. It does not have an implicit this pointer, cannot be invoked via obj.friendFunc(), and must access private members through explicitly passed object references.
6. Required Output Format for Each Problem:
• State exact line numbers and defect classification.
• Provide an in-depth root cause analysis referencing C++ standards.
• Provide the clean, compilable corrected code snippet.
• Provide the dry run and predicted terminal output.
B. Instructions for Pseudo-Code Writing Questions
When formulating pseudo-code for Object-Oriented designs:
1. Structural Class Syntax:
• Clearly delineate class sections: CLASS <Name>, PRIVATE:, PUBLIC:, ENDCLASS.
• Distinguish between instance attributes and STATIC class attributes.
• Indicate parameter passing mechanisms explicitly: by value vs. by reference (REF).
2. Method Definitions:
• Show constructor declarations (CONSTRUCTOR(...)), instance methods (METHOD ...), and class methods (STATIC METHOD ...).
• When demonstrating member functions defined outside the class, use scope notation (METHOD ClassName::MethodName()).
3. Traceability:
• Include a dry-run trace table tracking variable and object state across method calls.

// Line 11: Array element modifier

4. Show the dry-run and expected output of the corrected code.
