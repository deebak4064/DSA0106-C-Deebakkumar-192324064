UNIT IV: Inheritance & Pointers
Question Bank: Debugging & Pseudo-Code Formulation (Questions Only)

1. Syllabus & Topic Scope
• Inheritance Fundamentals: Concept of inheritance, code reusability, base class vs. derived class, access visibility specifiers (public, protected, private derivation).
• Types of Inheritance: Single, Multilevel, Multiple, Hierarchical, and Hybrid inheritance.
• Virtual Base Classes: The Diamond Problem (multipath inheritance duplication and ambiguity), resolving redundant subobjects using the virtual base inheritance specifier.
• Abstract Classes: Pure virtual functions as interfaces, incomplete classes, instantiability rules.
• Constructors in Derived Classes: Constructor execution order (Virtual base classes first, non-virtual base classes in order of declaration, member/composite objects, derived class constructor), passing arguments up the inheritance chain via the member initializer list.
• Member Classes (Containment / Composition): "Has-a" relationship vs. "Is-a" relationship, member object initialization.
• Pointers & Pointer Operations: Pointer declaration, address-of operator (&), dereference operator (*), pointer arithmetic.
• Pointers to Objects: Dynamic object instantiation (new), arrow operator (->), arrays of pointers to objects.
• The this Pointer: Implicit this pointer in non-static member functions, resolving parameter-field identifier shadowing, enabling method chaining (fluent interface) via return *this;.
• Pointers to Derived Classes: Upcasting (Base class pointer pointing to Derived class object), compile-time early binding limitations, object slicing phenomenon when copying polymorphic objects by value.

2. Assessment Instructions & Rules ("How to Do & What to Do")
A. Instructions for Debugging Questions
When debugging inheritance hierarchies and pointer mechanics in C++:
1. Analyze Multipath Inheritance (The Diamond Problem):
• When two intermediate classes inherit from the same base class and are joined by a derived class, check whether the base class was inherited as virtual. Missing virtual results in duplicate subobjects and member ambiguity errors (error: request for member is ambiguous).
2. Verify Constructor Invocation Chains:
• If a base class lacks a parameterless default constructor, verify that every derived class constructor explicitly invokes the base constructor in its member initializer list.
• Note that for virtual base classes, the most derived class is solely responsible for initializing the virtual base subobject.
3. Inspect Pointer Scope & Object Slicing:
• When using a base class pointer (Base*) pointing to a derived object, remember that the compiler only recognizes members declared in Base. Calling derived-specific members through Base* requires downcasting.
• If a derived object is assigned by value to a base object (Base b = derivedObj;), identify the Object Slicing bug where derived attributes and polymorphism are stripped.
4. Inspect this Pointer Chaining Semantics:
• For method chaining (obj.setA().setB()), check whether the method returns a reference ClassName& with return *this;. Returning a pointer ClassName* with return this; causes member dot operator syntax to fail.
5. Verify Access Visibility in Inheritance:
• Check whether inheritance is specified as private or protected. In private inheritance, public base members become private in the derived class, and upcasting outside the class becomes illegal (inaccessible base).
6. Required Response Format:
• State exact line numbers and defect category.
• Provide the theoretical explanation referencing class layouts and pointer type checking.
• Provide the clean, compilable corrected code snippet.
• Provide the dry run and console output.
B. Instructions for Pseudo-Code Writing Questions
1. Inheritance & Hierarchy Modeling:
• Clearly state inheritance syntax: CLASS Derived EXTENDS Base or CLASS Derived INHERITS Base1, VIRTUAL Base2.
• For abstract classes, prefix with ABSTRACT CLASS and tag unimplemented methods with ABSTRACT METHOD.
• Explicitly depict constructor delegation: CONSTRUCTOR(...) : BASE(...).
2. Pointers & References:
• Use explicit pointer notation: DECLARE ptr AS POINTER TO BaseType.
• Dynamic instantiation: ptr <- NEW DerivedType(...).
• Method chaining: RETURN REF THIS.

Topic: Hybrid Inheritance, Virtual Base Classes, Ambiguity
Problem Statement

public:
int idNumber;
Person(int id = 0) : idNumber(id) {
std::cout << "Person initialized: " << idNumber << std::endl;
}
};

// Line 12: Standard non-virtual inheritance
class Student : public Person {
public:
Student(int id) : Person(id) {}
};

// Line 18: Standard non-virtual inheritance
class Employee : public Person {
public:
Employee(int id) : Person(id) {}
};

// Hybrid inheritance combining Student and Employee
class TeachingAssistant : public Student, public Employee {
public:
TeachingAssistant(int sId, int eId)
: Student(sId), Employee(eId) {}

int main() {

// Line 33: Ambiguous member access!

return 0;

2. Draw or explain the memory layout of TeachingAssistant under non-virtual inheritance. Why are there two separate idNumber fields?
3. Refactor the classes using Virtual Base Class Inheritance to ensure that only a single, shared instance of Person exists.
4. Explain how constructor delegation changes when virtual base classes are used: Which constructor is responsible for invoking Person(int)?
