UNIT III: Constructors, Destructors and Operator Overloading
Question Bank: Debugging & Pseudo-Code Formulation (Questions Only)

1. Syllabus & Topic Scope
• Constructors: Definition, characteristics, default constructors, parameterized constructors, dynamic initialization of objects.
• Constructor Overloading: Multiple constructors with differing signatures, delegating responsibilities.
• Copy Constructors: Syntax ClassName(const ClassName &other), compiler-synthesized copy constructor, shallow copy vs. deep copy hazards.
• Dynamic Constructors: Allocating heap memory dynamically inside constructor bodies using new.
• Destructors: Syntax ~ClassName(), lifetime termination, cleanup of dynamically allocated resources (delete / delete[]), invocation order (reverse of constructor order).
• Defining Operator Overloading: Syntax and semantics of operator keyword, member operator functions vs. friend operator functions.
• Overloading Unary & Binary Operators: Overloading unary operators (prefix ++, postfix ++(int), unary -), binary arithmetic (+, -, *), relational (==, !=, <, >).
• Stream Insertion (&lt;&lt;) & Extraction (&gt;&gt;) Operators: Implementing stream I/O operators as non-member/friend functions.
• Rules for Overloading Operators: Un-overloadable operators (., .*, ::, ?:, sizeof), preserving precedence, associativity, and arity, prohibition of inventing new operators, requirement of at least one user-defined operand.

2. Assessment Instructions & Rules ("How to Do & What to Do")
A. Instructions for Debugging Questions
When debugging constructors, destructors, and operator overloading implementations:
1. Inspect Copy Constructor Signatures:
• Verify that the parameter is passed by reference (const ClassName &obj). Passing by value (ClassName obj) causes an infinite compilation recursion loop.
2. Examine Heap Resource Management (Rule of Three):
• If a class uses dynamic allocation (new / new[]) in its constructor and frees it in a destructor, check whether a custom Deep Copy Constructor is implemented. Missing deep copy results in Shallow Copy Pointer Aliasing and runtime Double-Free Heap Corruption.
3. Verify Operator Placement & Signatures:
• Stream Operators (&lt;&lt;, &gt;&gt;): Cannot be member functions when std::cout or std::cin appears on the left-hand side. They must be declared as non-member or friend functions returning std::ostream& / std::istream&.
• Prefix vs. Postfix Increment:
• Prefix (++obj): takes no arguments, modifies object, returns reference Type&.
• Postfix (obj++): takes dummy int token, captures old state, increments object, returns copy Type.
4. Enforce Language Overloading Constraints:
• Verify that non-overloadable operators (., .*, ::, ?:, sizeof) are never overloaded.
• Ensure at least one operand is a user-defined class or enum type. Built-in types cannot be overloaded.
5. Required Response Format:
• Identify line numbers and classify the bug.
• Provide the theoretical root-cause analysis referencing C++ memory models or grammar rules.
• Provide the clean, corrected C++ code.
• Show the dry-run output.
B. Instructions for Pseudo-Code Writing Questions
1. Lifecycle Modeling:
• Explicitly denote CONSTRUCTOR(...), COPY CONSTRUCTOR(REF other), and DESTRUCTOR().
• Model explicit heap allocation (ALLOCATE ARRAY[...]) and deallocation (DEALLOCATE pointer).
2. Operator Notation:
• Use formal operator signatures: OPERATOR +(REF other AS Type) RETURNS Type or FRIEND OPERATOR <<(REF stream, REF obj).
3. Deep Copy Logic:
• Demonstrate the allocation of a fresh memory buffer and the item-by-item copy loop inside copy constructors.

Question 1: Copy Constructor Pass-by-Value Infinite Recursion Trap
Topic: Copy Constructors, Parameter Passing Mechanisms
Problem Statement
A student designs a custom dynamic string class DynamicString that allocates character buffers on the heap. The student attempts to define a copy constructor to enable initialization of one string from another. However, the C++ compiler aborts compilation with a fatal error on the copy constructor signature.
Buggy Code
#include <iostream>
#include <cstring>

class DynamicString {
private:
char *buffer;
int length;

public:
// Parameterized Constructor
DynamicString(const char *str) {
length = std::strlen(str);
buffer = new char[length + 1];
std::strcpy(buffer, str);
}

// Line 17: Copy Constructor defined with Pass-by-Value!
DynamicString(DynamicString source) {
length = source.length;
buffer = new char[length + 1];
std::strcpy(buffer, source.buffer);
}

~DynamicString() {
delete[] buffer;
}

void print() const {
std::cout << buffer << std::endl;
}
};

int main() {
DynamicString s1("Antigravity C++");
DynamicString s2 = s1; // Intended copy construction
s2.print();
return 0;
}

Student Tasks
1. State the exact compiler error generated by Line 17.
2. Explain the theoretical mechanism: Why does passing source by value in a copy constructor lead to infinite recursive calls at compile time?
3. Provide the corrected copy constructor signature and explain the importance of adding the const qualifier and the pass-by-reference operator &.
4. Provide the complete compilable code snippet.

Question 2: Shallow Copy & Double-Free Runtime Crash
Topic: Dynamic Constructors, Destructors, Shallow vs. Deep Copy
Problem Statement
An audio processing class allocates dynamic heap storage for integer audio samples in its constructor and deletes the memory in its destructor. However, the author omits a user-defined copy constructor. When an object is passed by value to an analysis function, the program compiles cleanly but crashes violently during runtime with a heap corruption abort.
Buggy Code
#include <iostream>

class AudioBuffer {
public:
int *samples;
int capacity;

AudioBuffer(int cap) : capacity(cap) {
samples = new int[capacity];
for (int i = 0; i < capacity; ++i) {
samples[i] = i * 10;
}
std::cout << "Buffer allocated at: " << samples << std::endl;
}

// Programmer omitted copy constructor!

~AudioBuffer() {
std::cout << "Deallocating buffer at: " << samples << std::endl;
delete[] samples; // Crash occurs here during execution!
}
};

void processAudio(AudioBuffer buf) { // Passed by value!
std::cout << "Processing sample 0: " << buf.samples[0] << std::endl;
}

int main() {
AudioBuffer track(5);
processAudio(track);
std::cout << "Back in main, sample 0: " << track.samples[0] << std::endl;
return 0;
}

Student Tasks
1. Trace the memory address of samples before, during, and after processAudio(track) executes. What does the compiler-synthesized default copy constructor do to raw pointer members?
2. Explain why the program crashes with free(): double free detected when main() exits.
3. Write a user-defined Deep Copy Constructor that allocates fresh memory for the copied object and copies the elements individually.
4. Show the verified terminal output showing both distinct allocations and safe deallocations.

Question 4: Prefix vs. Postfix Increment Signature Inversion
Topic: Overloading Unary Operators (Prefix ++, Postfix ++(int))

Buggy Code

class StepCounter {
private:
int steps;

public:
StepCounter(int s = 0) : steps(s) {}

// Line 10: Intended as POSTFIX, but missing dummy int parameter

StepCounter temp = *this;
steps++;
return temp;
}

// Line 17: Intended as PREFIX, but includes dummy int parameter
StepCounter& operator++(int) {
steps++;

}

void display() const {
std::cout << "Steps: " << steps << std::endl;
}
};

int main() {
StepCounter c1(10);

// Developer expects prefix (++c1) to increment immediately and return modified object
StepCounter c2 = ++c1;
c2.display(); // Prints 10 instead of 11!
c1.display(); // Prints 11

return 0;
}

• Prefix increment (++obj)
• Postfix increment (obj++)
2. Explain the purpose of the dummy int parameter in postfix operator overloading.
3. Explain why prefix returns by reference (StepCounter&) while postfix returns by value (StepCounter).
4. Provide the corrected C++ code demonstrating accurate prefix and postfix behavior.
